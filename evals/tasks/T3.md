# T3 — Task Priority

*Frozen prompt. This exact text is given verbatim to Claude in both Condition A and Condition B — see `evals/protocol.yaml`. Do not add, remove, or reword anything below this line once the protocol is frozen.*

---

Add a `priority` field to `Task`.

Requirements:

- `priority` is one of `"low"`, `"medium"`, `"high"`.
- Creating a task without specifying `priority` must continue to work, and defaults to `"medium"`.
- A supplied `priority` value round-trips correctly through create, get, and list — what you send back on create is what a later `GET` returns.
- An invalid `priority` value (anything other than the three allowed strings) returns HTTP 422, not silently, and not a server error.
- **This repository already has a running database with existing task rows created before this change.** Your change must not break the ability to read or write tasks that were already in that database before `priority` existed — starting the application against that pre-existing database and using it normally must keep working, not just work against a freshly created empty database.

You will be given a copy of a pre-existing TaskFlow database (`evals/tasks/fixtures/T3_pre_existing_taskflow.db`) to develop and check against, in addition to the normal fresh-database case.
