# T1 — Task Pagination

*Frozen prompt. This exact text is given verbatim to Claude in both Condition A and Condition B — see `evals/protocol.yaml`. Do not add, remove, or reword anything below this line once the protocol is frozen.*

---

`GET /tasks/` currently returns every task in the database in one response. Add `limit` and `offset` query parameters so callers can page through results.

Requirements:

- Existing callers require no syntax change and the response remains a plain JSON array — with no explicit pagination parameters, the endpoint uses `limit=20` and `offset=0`.
- `limit` and `offset` are optional query parameters. `limit` defaults to 20 and must be between 1 and 100 inclusive. `offset` defaults to 0 and must be 0 or greater.
- A `limit` or `offset` outside those bounds is a client error (HTTP 422), not a silently clamped or ignored value.
- Pagination must compose correctly with the existing `done` filter — `GET /tasks/?done=true&limit=...&offset=...` must page through only the filtered set, not the full table.
- The response body's shape does not change — it is still a plain JSON array of task objects, not a new wrapper object with a total count or page metadata.
