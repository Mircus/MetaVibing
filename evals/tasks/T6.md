# T6 — Task Stats Endpoint

*Frozen prompt. This exact text is given verbatim to Claude in both Condition A and Condition B — see `evals/protocol.yaml`. Do not add, remove, or reword anything below this line once the protocol is frozen.*

---

Add a new endpoint, `GET /stats/tasks`, that returns task counts.

Requirements:

- Response body is a JSON object with exactly three integer fields: `total`, `pending`, and `completed`.
- `total` is the total number of tasks in the database. `completed` is the number where `done` is true. `pending` is the number where `done` is false. `pending + completed` must always equal `total`.
- If there are no tasks at all, all three fields are `0`, not an error.
- **Every existing endpoint must keep its current status codes and response shapes exactly as they are now.** This is a pure addition — nothing about `/tasks/`, `/tasks/{id}`, `/tasks/{id}/complete`, `/users/`, or `/users/{id}` should change as a side effect of this work.
